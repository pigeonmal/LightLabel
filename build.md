You are a senior macOS engineer specializing in Swift, SwiftUI, AppKit, Core ML, Vision, computer vision datasets, and high-performance desktop applications.

Build a complete, production-quality native macOS application for manually annotating computer vision datasets, with optional local AI-assisted annotation.

Do not build a web application. Do not use Electron, React Native, Flutter, Python as the application runtime, or any embedded web view. The final application must be a lightweight native macOS app written in Swift.

# Product goal

Create a lightweight, fast, offline-first macOS dataset annotation application for Apple Silicon Macs.

The application must support:

* Object detection with bounding boxes
* Instance segmentation with polygons
* Image dataset browsing and previewing
* Manual annotation
* Local AI-assisted annotation
* YOLO-format dataset import and export
* COCO JSON dataset import and export
* Undo and redo
* Autosave
* Keyboard-driven workflows
* Large datasets without loading every image into memory

The app should feel like a polished native Mac application rather than a cross-platform development tool.

Use a working product name such as “LightLabel” throughout the code, but organize the code so the product can easily be renamed later.

# Target platform

* Native macOS application
* Swift 6 or the latest stable Swift version supported by the installed Xcode
* SwiftUI for the main interface
* AppKit integration where SwiftUI is insufficient

* Apple Silicon optimized
* No Intel-specific dependency

# YOLO dataset support

Support YOLO object-detection datasets.

Import common layouts such as:

```text
dataset/
├── data.yaml
├── images/
│   ├── train/
│   ├── val/
│   └── test/
└── labels/
    ├── train/
    ├── val/
    └── test/
```

Also support a flat directory when image and label files are paired by filename.

Parse standard YOLO detection lines:

```text
class_id center_x center_y width height
```

All values except the class ID are normalized.

Support importing class names from common `data.yaml` representations, including indexed and array forms.

Do not require a full YAML framework if a small, well-tested parser can reliably handle the required subset. If a third-party YAML library is used, justify it in the project documentation.

Export:

* Label text files
* Dataset folder structure
* `data.yaml`
* Class mapping
* Train, validation, and test splits

Report malformed rows with the image filename and line number.

# YOLO segmentation support

Support YOLO segmentation labels using normalized polygon coordinates in the standard form:


Automatically distinguish valid detection rows from segmentation rows based on the active import mode or dataset configuration.

Export polygon annotations to the YOLO segmentation format.

When exporting unsupported geometry, show a clear compatibility warning and never silently discard annotations.

* Produce deterministic IDs

# Persistence and autosave

The original dataset files must remain the primary user-owned data.

Do not force users to import their dataset into a proprietary package.

Create a small hidden project metadata directory when needed:

```text
.lightlabel/
├── project.json
├── state.json
├── autosave.json
├── thumbnails/
└── model-settings.json
```

Use atomic file writes.

Avoid rewriting every annotation file after every pointer movement.

Autosave after a short debounce when an annotation operation completes.

Track dirty files and only rewrite files that changed.

Before overwriting files, preserve recoverability through either:

* Atomic replacement
* Backup snapshots
* A lightweight recovery journal

On launch, detect an unfinished autosave session and offer recovery.

# Performance requirements

Requirements:

* Do not load all full-resolution images into memory
* Use lazy loading
* Use thumbnail downsampling
* Use `NSCache` or an equivalent bounded cache
